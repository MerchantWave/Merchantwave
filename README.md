# MerchantWave

MerchantWave is a mobile-first merchant finance and network demo for Liberia. It combines a local bookkeeping ledger, merchant directory, activity insights, voice input, and nationwide operations views in one application.

## Run locally

Requirements: Node.js 20.19+ or 22.12+ and npm.

```sh
npm install
cp .env.example .env.local
npm run dev
```

Open the URL printed by Vite. `npm run build` creates the production bundle in `dist/`; `npm run preview` serves that bundle locally.

## Demo behavior and data

The app works without credentials. Choose **Open demo workspace** to use the seeded Liberia/L$ dashboard. Ledger entries and preferences are saved in this browser's `localStorage`; they are not synced, encrypted, backed up, or protected by an account. The demo sign-in screen does not accept or save passwords. Do not enter real financial or personal data.

Merchant names, records, transaction history, county rollups, and map coordinates are illustrative seed data—not verified businesses, payments, or a live national registry. The map includes 160 generated demo merchant pins. Without a Google Maps key, the app shows a clearly labeled county-oriented schematic instead of implying that it is a navigable geographic map. Route links open Google Maps in a new tab.

## Optional integrations

### Google Maps JavaScript API

Set `VITE_GOOGLE_MAPS_API_KEY` in `.env.local` and enable Maps JavaScript API for that key. The Network page then renders the Google hybrid satellite/road map, merchant pins, and in-map driving routes. Restrict the key to the deployed site origin and API; a browser key is public by design and must not have server-side privileges. The app falls back to the labeled schematic if no key is configured.

### AI gateway and WAV transcription

Set `VITE_AI_GATEWAY_URL` to a trusted, same-origin or CORS-enabled server endpoint that accepts `POST` requests with `multipart/form-data` fields `audio` (a WAV file) and `prompt`. The endpoint must authenticate and authorize the current user, validate file type and size, keep provider secrets on the server, and return JSON in the form `{ "transcript": "..." }`. The browser never receives a Gemini key. Without this endpoint, WAV upload is not sent anywhere and the UI explains that transcription is unavailable. Dormancy and root-cause insights are calculated locally from the demo ledger, not generated by Gemini.

## Production integration checklist

This repository currently contains a front-end demo only. It does not include a backend, PostgreSQL/Lovable Cloud project, row-level security policies, real authentication, payment processing, push alerts, or AI gateway. Before handling real merchants or money, add a trusted identity provider and server-side authorization, a database with per-user row-level security, audit logging and backups, and a secured server-side integration for maps/AI. Never treat localStorage or client-side checks as access control.

The interface includes English, French, Portuguese, Spanish, Arabic, Chinese, Hindi, and Swahili language choices, plus light and dark themes. Localization currently covers the main application navigation and key dashboard actions; some demo content and detailed record descriptions remain in English.
